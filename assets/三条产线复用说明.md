## 先选一条与你需求接近的产线

| 产线 | 内容起点 | 核心能力 | 输出 |
| --- | --- | --- | --- |

## 01 Reddit Daily

输入：原帖、作者演示、可使用的视频素材、栏目规则。

路径：检索 → 核实与筛选 → 写稿 → 配音 / 字幕 / 卡片 / 剪辑 → 发布 → 复盘写回 Skills。

分工：Codex 按 Skills 串联任务；ChatCut 承担可编辑的视频工程；数据工作台记录素材、脚本版本与发布反馈。

最重要的人工判断：这个项目哪里值得看；画面是否清晰流畅；文案和声音是否自然；品牌是否确实参与案例。涉及商业合作按平台要求标注。

复用时先准备：目标受众、固定栏目结构、三条有来源且有画面的样例、字幕和声音参考。先做一条完整样片，再改规则，不要先堆提示词。

当前证据：用户提供截图中一条小红书视频 18,200 播放；YouTube 部分视频千级。不是稳定流量保证，也不是注册或付费转化。

## 02 Claude 动效视频

输入：1–2 条风格参考、Logo、品牌颜色和字体、真实产品截图与演示，以及观众、重点、时长、比例和行动目标。

路径：整理参考与品牌素材 → 配置一种主要制作环境 → Claude 提三版分镜 → 人选一个方向 → 每镜先看关键静帧 → 制作动效 → 逐镜修改 → 检查并渲染 MP4。

技术分工：Claude 组织镜头并编写场景代码；HyperFrames 或 Remotion 负责制作与渲染，不要求两套同时使用。HyperFrames 使用 HTML/CSS 等网页技术、浏览器逐帧渲染和 FFmpeg；Remotion 使用 React 场景及按帧编排。21st.dev 是可选的 UI 组件来源，需检查许可并适配，不替代自己的产品界面。

最重要的人工判断：参考具体借鉴什么、分镜方向是否符合目标、静帧层级与手机可读性、产品事实是否准确。静帧确认以后再调运动，不让模型跳过确认直接整片渲染。

修改要具体到镜头和元素。例如“第三镜推进速度降到 0.7×”“这里硬切到按钮”“标题多停 0.5 秒”。先局部预览，再完整检查画面、字幕、声音和安全区；输出 MP4，同时保留源项目和素材。

适合留进 Skills：参考整理要求、品牌约束、分镜与静帧确认点、定向修改规则、出片检查。当前分享的是可借鉴的方法，不代表已验证“一条提示词”即可稳定产出专业成片，也不代表每次修改只改一行。

官方资料：[WhatShips](https://whatships.com/) · [HyperFrames](https://github.com/heygen-com/hyperframes) · [Remotion](https://www.remotion.dev/docs/idea) · [21st.dev](https://21st.dev/)。接入要求与许可以各工具当前说明为准。

## 03 Hollymoly

输入：一个明确的游戏玩法、可观察的状态、自动演示或策略接口、画面与故事方向。

路径：讨论创意 → 游戏提示词 → 首尾概念图 → 平台构建 → 游玩录制 → 脚本配音 → 视觉包装 → 合成 → 人工验收。

录制方法：策略读取游戏状态并操作，按固定时间步长采集帧，状态日志帮助定位吃到物体、升级、胜负等事件。不要把这种机制描述为已经证实的大模型逐帧看屏游玩。

叙事方法：先给最强结果 → 回到开始 → 玩法逐步升级 → 结尾提问。以“我做了这个游戏”为出发点，不做游戏功能清单。

配音方法：完整一段生成，多版本听审，保留自然呼吸；动作、词锚点和音效在同一条时间线上对齐。

最重要的人工判断：游戏本身是否有过程与变化；录屏是否真的展示了叙述的事件；前几秒是否成立；口播是否像同一个人在说话。

当前状态：按《HOLY MOLLY 产线》说明，雪球案例已验证从脚本到成片；新游戏与 Windows 仍需测试。网页嵌入的是用户提供的真实样片，并非本次重新运行完整生产线。

## 同事第一次怎么接

1. 说清楚你要给谁看，以及观众看完应该知道或做什么。
2. 从三条产线中选最近的一条，提供一份可用素材或一个玩法。
3. 与 Kevin 对齐工程版本、账号权限、素材使用范围与人工确认点。
4. 先跑一条，从头看完、听完；记录耗时、返工和问题。
5. 发布后记录流量与有效反馈；如需评估业务价值，再接入点击、注册、使用等归因。
6. 只把经核实且可复用的经验写回 Skills，保留版本。
